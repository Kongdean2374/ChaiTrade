# 瀏覽與交易草稿的儲存競態

App1.2.27（30）候選，以下新斷言仍須同提交原生／核心完整實跑。版本與結果以[目前驗證](VALIDATION_CURRENT.md)為準；未執行不列通過。

正常ETH瀏覽出現舊保存警告的原圖／原包見[evidence/RETAINED_1_2_24_BROWSING_AND_PAGE_FAILURES.md](evidence/RETAINED_1_2_24_BROWSING_AND_PAGE_FAILURES.md)。搜尋與交易編輯原先都可由下一次輸入取消已進入儲存的防抖任務；SQLite查核會尊重取消並回滾。兩者改成獨立單一寫入者，防抖只取消等待，待存變更在寫入期間仍保留並合併。真正失敗保留待存及對應警告；成功只清除自己的舊警告，不清除其他訊息。帳戶重綁定以context／generation隔離舊回呼；交易原revision與完整身份驗證保留。

另修訂單表單返回初始欄位值的狀態：首次未編輯呈現不建立草稿，但使用者編輯後改回原值必須保存，不能被`baseline`條件忽略。沒有新送單、重設帳戶或修改資金；原SQLite交易、備份格式、來源及A／B資料隔離保留。

核心`cancelledBrowsingWriteRollsBackWithoutPoisoningNextCommit`分別取消真實瀏覽／交易草稿儲存，要求CancellationError，逐位元核對記憶體與磁碟原狀不變，再要求新搜尋與新revision草稿可提交；核對資金、委託、成交、帳本與模擬時間不變。新原生搜尋案例刻意交錯搜尋2330→233，再冷啟動核對最新值。既有草稿冷啟動案例保留並加強為數量1→3（儲存等待中）→1（回原值）→7，要求真正保留最新編輯、沒有舊取消警告，背景／前景／冷啟動後商品、方向及7仍一致，且沒有送單或移動資金。

同步只在DEBUG獨立測試帳戶啟用，僅控制真實UI編輯與真實SQLite呼叫的先後，不回傳假的成功結果；Release不包含測試旗標。兩種受控等待各有15秒上限，原案例120秒不變；新增案例與全部原測試仍保留，共186核心及80次UI。實體iPhone原2秒冷啟動與150ms操作回饋仍需簽署及實機驗證。

# 互動 Bug 專項驗證

狀態：新增回歸案例，尚待首次 Apple 基準執行。既有正常流程通過不能代表以下案例已通過。

每個 UI 測試建立獨立 UUID 資料目錄；同一案例內重啟保留其資料，其他案例不能共用委託、日誌或自選。舊的模式切換案例現在自行建立部位，不依賴另一案例。

| 案例 | 驗證 |
|---|---|
| 快速保存日誌 | 鍵盤開啟後五連點，保存恰好一筆，內容不變，程序重啟仍僅一筆 |
| 快速下單／取消 | 多次開確認、取消零副作用、五連點確認後一筆委託／成交，現金與帳本精確對帳，重啟不重扣 |
| Tab 切換／重點與自選 | 儲存等待期間四次自選切換必須保留四個意圖；再加入並連切／重點多個 Tab，重啟仍保留 |
| 返回／關閉／鍵盤 | 多層返回、邊緣返回、日誌取消與滑下、下單滑下、鍵盤不阻擋必要按鈕；未確認不寫入 |
| 補算中操作 | 下單面板已開時啟動真實引擎補算，禁止提交；暫停保存檢查點，多次繼續僅完成一次且不產生委託 |

Debug 測試版提供唯讀 JSON 狀態探針。兩商品的小型離線 fixture 使用正式引擎與 SQLite；部分案例在非同步儲存入口或真實補算檢查點加入受控等待，讓輸入能穩定交錯。這些控制不編入 Release IPA，不用來宣稱效能。

每次失敗先保留截圖、accessibility hierarchy、狀態 JSON，並由 Actions 的 always 區段保留 xcresult、日誌及僅限測試 UUID 的資料庫。修復前後分別記錄 commit/run，不以重試正常流程取代失敗斷言。

所有 T45 門檻與單一 UI 案例 120 秒上限不變；UI 工作總預算因獨立初始化與新增案例由 12 分鐘改為 25 分鐘。

## 寫入路徑與修正

每次原子保存仍會精確查核完整fills／ledger／events／equity等筆數。帳本與估值的COUNT(*)原本必須掃描含完整JSON的大表；新增兩個小型account_id覆蓋索引，讓相同精確查詢可讀較窄索引。沒有改為max(ordinal)、估計筆數或易漂移的快取計數。

原本熱投影裡所有委託每次都做UPDATE，即使內容完全相同，造成額外WAL及索引寫入；現在僅在status、payload或time變更時更新。新委託、撤單、部分成交、修改與費用仍保存，同一SQLite交易的全部財務驗證、immutable重複內容比對與synchronous=FULL保持不變。沒有延後持久化或先回成功。

完整封存保持嚴格結構白名單，僅額外明列「舊編譯結構缺少這兩個新效能索引」這一種完整舊結構；不接受任意缺少／修改索引或自訂觸發器，不在匯入檔案執行遷移。既有帳戶啟動時安全新增索引，不刪除、清空或更換帳戶資料。
